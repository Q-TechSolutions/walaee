دليل الفريق ودورة حياة التطوير

مَن يعمل ماذا، ومتى، وبأي معيار يُقبل عمله. هذا المستند يحسم الأدوار والمسؤوليات ونقاط التسليم بين التخصصات، بحيث لا يوجد بند بلا صاحب ولا تسليم بلا معيار قبول.

٦ تعريف الجاهز وتعريف المنجز

Definition of Ready — قبل دخول السبرنت

✓ القصة مكتوبة بصيغة «كـ… أريد… حتى…»
✓ معايير القبول محددة وقابلة للاختبار
✓ التصميم جاهز ومعتمد (إن كانت واجهة)
✓ عقد API متفق عليه (إن كانت تمس الخلفية)
✓ التبعيات معروفة وغير حاجبة
✓ مقدّرة من الفريق — لا من شخص واحد
✓ تُنجَز داخل سبرنت واحد — وإلا تُقسَّم

Definition of Done — قبل الإغلاق

✓ الكود مدموج في develop وكل البوابات خضراء
✓ اختبارات وحدة وتكامل مكتوبة وناجحة
✓ التوثيق محدّث (API + README)
✓ حالات التحميل والخطأ والفراغ منفّذة
✓ RTL مضبوط ومختبَر على جهاز حقيقي
✓ QA اعتمدها على بيئة التجريب
✓ PO شاهدها تعمل واعتمدها
✓ منشورة على Staging وتعمل
لماذا هذان التعريفان تحديدًا؟ لأن أكثر ما يُفشل الفرق الصغيرة ليس ضعف المهارة، بل الاختلاف الصامت على معنى «خلصت». تعريف مكتوب ومعلّق يحسم الجدل قبل أن يبدأ.
