# الأمان والصلاحيات

## مصفوفة الأدوار

| الدور | النطاق | يستطيع |
|---|---|---|
| `customer` | نفسه فقط | بطاقاته · مسح · استبدال · حذف حسابه |
| `cashier` | فرع واحد | تأكيد العمليات وصرف الأكواد — **لا يرى التقارير** |
| `manager` | فرع أو أكثر | العملاء · المكافآت · الحملات · التقارير |
| `owner` | العلامة كاملة | القواعد · الفروع · الاحتيال · الفوترة |
| `platform_admin` | المنصة | المتاجر والاشتراكات — **لا يرى بيانات شراء الأفراد** |

---

## الضوابط المطبّقة

| الضابط | التنفيذ |
|---|---|
| عزل بيانات العلامات | `BrandScopedQuerySet` يُطبَّق على مستوى المدير الافتراضي |
| تحديد معدل OTP | ٣ محاولات / ١٥ دقيقة لكل رقم **ولكل IP** |
| عمر التوكن | وصول ١٥ دقيقة · تحديث ٣٠ يومًا مع إبطال |
| تشفير عند التخزين | قرص مشفّر + تجزئة أرقام الهواتف في السجلات |
| حماية الحقن | ORM حصرًا — لا SQL خام في أي مسار |
| سجل تدقيق | Middleware يلتقط كل تغيير مع الفاعل و IP |
| حق الحذف | حذف ناعم ٣٠ يومًا ثم إخفاء هوية القيود نهائيًا |
| الأسرار | متغيرات بيئة فقط — لا شيء داخل المستودع |

---

## تعارض متعمّد ومحلول

**حق العميل في الحذف يصطدم بقاعدة «القيود لا تُحذف».**

الحل: تُحذف بيانات الهوية (الاسم والهاتف والتوكنات) وتبقى القيود بمعرّف مجهول —
فيُحترم حق العميل ويظل رصيد التاجر متوازنًا.

هذا القرار **يُوثَّق في عقد معالجة البيانات** مع التاجر.
