## ما هذا المستودع؟

مشروع **ولائي**: منصة SaaS لإدارة برامج الولاء تربط العميل وصاحب المتجر في تجربة واحدة.
المستودع يحتوي على كل ما أُنتج قبل بدء التنفيذ:

| المخرج | الوصف |
|---|---|
| **نموذج عرض تفاعلي** | ٢٤ شاشة عبر ٣ واجهات — قابلة للتصفح بالكامل |
| **عرض تقديمي 3D** | ١٨ شريحة بانتقالات ثلاثية الأبعاد وواجهات حيّة مدمجة |
| **تحليل شامل** | ٢٤ صفحة PDF: ٨ نقاط قوة، ١٦ مشكلة بحلولها، الجدوى |
| **خطة التطوير** | ٦ مراحل بمعايير قبول + ٣ باقات تسعير |
| **المخطط المعماري** | ٢١ جدولًا، ٤٧ نقطة API، الكود الحرج، الحاويات |
| **Docker** | جاهز للنشر على Dokploy |

> ⚠️ البيانات المعروضة في النموذج **تجريبية لأغراض التقديم فقط**. لا يوجد backend ولا قاعدة بيانات بعد.

## التشغيل

### محليًا بدون أي تنصيب

افتح `demo/index.html` بأي متصفح. لا يحتاج سيرفر ولا إنترنت.

### عبر Docker

```bash
docker build -t walaee-demo .
docker run -d -p 8080:80 walaee-demo
# http://localhost:8080
```

أو:

```bash
docker compose up -d --build
```

### النشر على Dokploy

خطوات كاملة في **[`DEPLOY.md`](DEPLOY.md)**.
باختصار: `Create → Compose` → اربط المستودع → `Domains: Service=web · Port=80` → فعّل HTTPS → Deploy.

الصورة **~٨٢ ميجابايت** وتستهلك **~١٧ ميجابايت** ذاكرة.

## القرارات المعمارية الأساسية

هذه القرارات مشروحة بالتفصيل في `demo/architecture/`:

1. **`LedgerEntry` بنمط append-only** — لا تعديل ولا حذف. أي تصحيح بقيد عكسي.
   هذا ما يجعل «الالتزام القائم» رقمًا قابلًا للدفاع عنه أمام محاسب التاجر.
2. **`select_for_update()` على الرصيد** — بدونه، ضغطتان متزامنتان على «تأكيد» تمنحان النقاط مرتين.
3. **التسلسل الهرمي من اليوم صفر** — مؤسسة ← علامة ← فرع ← نقطة بيع ← مستخدم.
   بناؤه لاحقًا يكلّف ٣–٦ أشهر ترحيل بيانات.
4. **رصيد منفصل لكل علامة** — يتجنّب تحوّل المنصة إلى نظام مقاصة مالية بين التجّار.
5. **مفاتيح ميزات حسب الباقة** — الباقات الثلاث من قاعدة كود واحدة.
