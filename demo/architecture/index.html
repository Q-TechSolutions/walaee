٤ نموذج البيانات والعلاقات

٢١ جدولًا. أهم قرار في المشروع كله — بناؤه صحيحًا الآن يكلّف أيامًا، وتعديله بعد الإطلاق يكلّف شهورًا.

الهيكل والحسابات الولاء القيود (append-only) التشغيل الفوترة التكاملات PK مفتاح أساسي FK مفتاح خارجي UQ فريد IX فهرس

٥ تدفق تنفيذ العملية الحرجة

دورة «رمز ← مسح ← تأكيد ← نقطة» — الطريق الذي يمر به كل جنيه في النظام.

١
تدوير رمز نقطة البيع

مهمة Celery Beat كل ٣٠ ثانية تولّد رمزًا جديدًا لكل Terminal نشط وتخزّنه في Redis بمفتاح pos:code:{code} → terminal_id مع TTL=35s. شاشة الكاشير تسحبه عبر GET /pos/code أو قناة SSE.

٢
العميل يمسح الرمز

POST /scan/resolve {code} — الخادم يقرأ Redis. غير موجود أو منتهٍ ← 410 Gone. ناجح ← يرجع بيانات العلامة والفرع والبرامج النشطة ومعاينة الرصيد الحالي.

٣
إدخال قيمة الفاتورة

POST /transactions {terminal_id, invoice_amount, invoice_no} ← ينشئ سجلًا بحالة pending. لا تُمنح أي نقطة في هذه الخطوة. يُستهلك الرمز من Redis فورًا حتى لا يُعاد استخدامه.

٤
التاجر يؤكّد — المعاملة الذرية

POST /pos/transactions/{id}/confirm يفتح معاملة قاعدة بيانات واحدة تنفّذ: قفل صف العضوية ← تطبيق القاعدة ← فحص السقوف ← كتابة القيد ← تحديث الرصيد ← سجل التدقيق ← قواعد الاحتيال. إما أن ينجح كل ذلك أو لا يحدث شيء.

٥
ما بعد التأكيد — غير متزامن

بعد نجاح المعاملة تُطلق مهام Celery: إشعار Web Push للعميل، إطلاق Webhook للأنظمة المرتبطة، تحديث المؤشرات المجمّعة، وإعادة حساب «الالتزام القائم» للفرع. فشل أي منها لا يؤثر على صحة الرصيد.

٦
الاستبدال

POST /redemptions {reward_id} ← نفس النمط الذري: قيد بـ delta سالب وreason=redeem، ثم توليد كود صالح ١٥ دقيقة يعرضه العميل على الكاشير.

٧
انتهاء الصلاحية — مهمة ليلية

مهمة يومية تبحث عن الأرصدة المنتهية وتكتب قيدًا بـ reason=expire، وترسل تنبيهًا مجانيًا قبل الانتهاء بثلاثين يومًا.

٦ الكود الحرج — محرك القيود

هذه الدالة هي المكان الوحيد في المشروع الذي يعدّل الرصيد. أي مسار آخر يمر عبرها.

apps/ledger/services.py
from django.db import transaction
from django.db.models import F

class LedgerError(Exception): ...
class DailyCapExceeded(LedgerError): ...

@transaction.atomic
def apply_entry(*, membership, program, delta, reason,
                transaction_obj=None, reverses=None, actor=None):
    """المكان الوحيد الذي يُعدَّل فيه الرصيد. ذرّي ومقاوم للتزامن."""

    # 1) قفل صف الرصيد — يمنع التنفيذ المتوازي لنفس العضوية
    balance = (Balance.objects
               .select_for_update()                 # ← يقفل الصف حتى COMMIT
               .get_or_create(membership=membership, program=program,
                              defaults={"amount": 0})[0])

    rule = program.rule

    # 2) السقف اليومي — يحمي من الاحتيال الداخلي (م‑07)
    if delta > 0 and rule.max_per_day:
        earned_today = LedgerEntry.objects.filter(
            membership=membership, program=program, reason="earn",
            created_at__date=timezone.localdate(),
        ).aggregate(s=Sum("delta"))["s"] or 0
        if earned_today + delta > rule.max_per_day:
            raise DailyCapExceeded(membership.id)

    # 3) منع الرصيد السالب
    new_amount = balance.amount + delta
    if new_amount < 0:
        raise LedgerError("insufficient_balance")

    # 4) القيد — إضافة فقط، لا تعديل ولا حذف أبدًا
    entry = LedgerEntry.objects.create(
        membership=membership, program=program, delta=delta,
        reason=reason, transaction=transaction_obj,
        reverses=reverses, balance_after=new_amount,
    )

    # 5) تحديث اللقطة ذرّيًا على مستوى قاعدة البيانات
    Balance.objects.filter(pk=balance.pk).update(
        amount=F("amount") + delta,
        expires_at=compute_expiry(rule),
        updated_at=timezone.now(),
    )

    # 6) سجل تدقيق غير قابل للحذف
    AuditLog.record(actor=actor, action=f"ledger.{reason}",
                    entity=entry, after={"delta": delta,
                                        "balance_after": new_amount})
    return entry


@transaction.atomic
def reverse_entry(entry, *, actor=None):
    """التصحيح الوحيد المسموح: قيد عكسي جديد — لا UPDATE ولا DELETE."""
    if entry.reversed_by.exists():
        raise LedgerError("already_reversed")
    return apply_entry(
        membership=entry.membership, program=entry.program,
        delta=-entry.delta, reason="reverse",
        reverses=entry, actor=actor,
    )
apps/pos/services.py — تأكيد العملية
@transaction.atomic
def confirm_transaction(txn_id, *, staff_user):
    txn = Transaction.objects.select_for_update().get(pk=txn_id)

    if txn.status != "pending":
        raise LedgerError("not_pending")          # حماية من التأكيد المزدوج
    if staff_user.branch_id != txn.terminal.branch_id:
        raise PermissionDenied                     # كاشير فرع آخر

    membership, _ = Membership.objects.get_or_create(
        customer=txn.customer, brand=txn.terminal.branch.brand)

    entries = []
    for program in active_programs(txn.terminal.branch.brand):
        delta = compute_delta(program.rule, txn.invoice_amount)   # حسب النموذج
        if delta:
            entries.append(apply_entry(
                membership=membership, program=program, delta=delta,
                reason="earn", transaction_obj=txn, actor=staff_user))

    txn.status = "confirmed"
    txn.save(update_fields=["status"])

    # قواعد الاحتيال داخل نفس المعاملة — لا تُؤجَّل
    fraud.evaluate(txn)

    # المهام غير المتزامنة تُطلق بعد نجاح COMMIT فقط
    transaction.on_commit(lambda: notify_customer.delay(txn.id))
    transaction.on_commit(lambda: dispatch_webhook.delay("transaction.created", txn.id))
    return entries
السطر الأهم في المشروع كله: select_for_update(). بدونه، لو ضغط الكاشير «تأكيد» مرتين بسرعة، أو مسح عميلان في نفس اللحظة، ستُمنح النقاط مرتين ويختل الرصيد. هذا سيناريو يجب أن يغطيه اختبار تزامن صريح قبل الإطلاق.
